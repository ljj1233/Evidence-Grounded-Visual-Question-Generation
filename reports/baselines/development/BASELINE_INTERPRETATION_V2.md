# Baseline interpretation v2

The formal SFT audit selects `CLEAN_WITH_TEXT_OVERLAP_CAVEAT`. Image IDs are disjoint across SFT train/dev/test, the 1,000-image development set, reward calibration, and final holdout. The loader consumes only image and question fields, and the loss masks image/prompt tokens so only assistant question tokens contribute. The caveat is exact normalized question/template overlap with VQAv2 references, not image leakage: 34.24% of reward-calibration reference records and 33.88% of final-holdout reference records have a normalized question string seen in SFT train. This is disclosed and no records were removed.

The final SFT checkpoint is a valid primary baseline for the frozen development protocol. It is the final step after two epochs (6,250 steps), with train loss 1.16279 and dev loss 1.305293; no reward-calibration, final-holdout, or val2014 selection was found. The training summary has a path spelling mismatch, which is retained as a provenance note; the protected checkpoint itself is unchanged.

The main matrix contains only the internal Zero-shot and final-SFT rows. InfoMax, ConVQG, Double Hints, and ED-VQG require answer, textual, ROI, or scene-graph inputs. Guiding VQG has an adaptable implicit variant but no released checkpoint and its explicit variant requires guidance inputs. The SeeQ method checkpoint is unavailable by design. These methods remain in the external/different-input table and are not forced into an apples-to-apples score table.

SFT improves conventional reference metrics on the same 1,000 images: BLEU-4 0.089809 to 0.317225, CIDEr 0.126362 to 0.454971, and Q-BLEU variant 0.087013 to 0.310714. Independent visual-support labels also improve: supported 0.634 to 0.725 and unsupported 0.230 to 0.159. Greedy diversity worsens: Distinct-2 0.276117 to 0.139524 and duplicate rate 0.121 to 0.570.

Under the released SeeQ rubric with GPT-5.6 Luna, the one-question project protocol gives Zero-shot versus SFT normalized means of Search 0.367968 vs 0.274600, Coverage 0.402202 vs 0.259800, Context 0.365966 vs 0.270400, and Spatial 0.124725 vs 0.073200. These are documented judge-substitution scores, not official SeeQ scores; the paper uses GPT-5.4 and five questions per image. A matched GPT-4o audit preserves the SFT-below-Zero-shot direction on all four dimensions, while spatial rank agreement is weak and absolute calibration differs.

The SeeQ evaluator is therefore available with a judge substitution; the trained SeeQ method is unavailable. The Qwen3-Embedding-4B diversity implementation now runs from the ModelScope-verified local weights. Mean within-image cosine distance is 0.393691 for Zero-shot and 0.536019 for SFT, with 95% bootstrap intervals [0.377961, 0.409391] and [0.526991, 0.545292]. This is a four-question project protocol and is not directly comparable to SeeQ’s five-question paper values.

The results answer the current scientific question: SFT improves conventional VQG overlap and visual support while making the generated questions less visually demanding under this rubric and less diverse under greedy decoding. This is a capability profile, not a master score. It does not authorize GRPO, reward-weight changes, retraining, or final-holdout evaluation.

For the remaining checklist questions: the SFT checkpoint is a valid primary baseline (`YES`); image-level leakage is absent (`NO`); the reported train/evaluation overlap is textual/template overlap only; Search, Coverage, Context, and Spatial all decrease under SFT in the Luna run; semantic diversity is 0.393691 for Zero-shot and 0.536019 for SFT; sampled semantic diversity increases, while greedy lexical diversity still decreases. The dominant residual SFT visual violations are ambiguous references (6.4%) and unobservable targets (12.2%), with external-knowledge-required at 0.4%. No external method is currently a direct frozen baseline; the most useful future comparisons are image-only released checkpoints or a separately approved adaptable reproduction. The semantic-diversity measurement is now complete, so the Phase 2.4 decision is `READY_FOR_OFFLINE_REWARD_AUDIT`; no GRPO is started automatically.
