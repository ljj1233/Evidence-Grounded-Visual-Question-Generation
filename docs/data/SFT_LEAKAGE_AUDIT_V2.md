# SFT Leakage and Provenance Audit v2

The final Qwen3-VL-8B LoRA checkpoint is **CLEAN_WITH_TEXT_OVERLAP_CAVEAT** and remains acceptable as the primary SFT baseline. The audit uses COCO `image_id` as the authoritative identity and leaves the checkpoint, SFT data, reward-calibration corpus, final holdout, Phase 2.3 predictions, and VIC definition unchanged.

The image lineage is disjoint across SFT train (9,184 images), SFT dev (423), SFT internal test (351), `val_debug` (1,000), reward calibration (1,000), and final holdout (2,000). Every off-diagonal image-id intersection is zero. Deterministic path intersections are also zero, and no cross-split inode aliases or symlink paths were found. The complete matrix is in `outputs/phase24/sft_audit/lineage_audit.json`. The raw COCO tree is 46 GB, so the audit uses authoritative image IDs plus path/inode checks rather than re-hashing every JPEG.

All 54,000 SFT records on disk have exactly the fields `{image, question}`. The actual loader in `src/vvqg/training/train_sft.py` reads only those two fields. The processor receives the image and the fixed instruction, with the question as the assistant target. The collator builds causal-LM labels and masks padding and all user/image prompt positions; only assistant question tokens contribute to loss. No answer, rationale, reward, evidence, scene graph, validation metadata, or holdout metadata is present or consumed. Details are in `record_content_audit.json`.

The dataset manifest and construction code identify VQAv2 `train2014` questions as the sole SFT source. `val2014` questions are reserved for evaluation, and the preparation code excludes the evaluation image pool before sampling train/dev/test. The checkpoint was trained for two epochs and saved at the final step (6,250). Dev loss was evaluated after training; the training code has no best-checkpoint selection, val2014 metric selection, reward selection, or final-holdout selection path. The checkpoint-selection evidence is in `checkpoint_selection_audit.json`. The training summary records a legacy `outputs/sft/...` path spelling while the protected artifact is under `outputs/checkpoints/...`; this provenance inconsistency is recorded without changing either file.

Normalized exact question text overlaps naturally across VQAv2 images. Using Unicode NFKC, casefolding, whitespace collapse, and retained punctuation, 34.240% of reward-calibration reference records and 33.878% of final-holdout reference records have a string appearing in SFT train. The corresponding unique-string rates are 26.548% and 22.919%. Frequent templates include “what is the man doing?”, “what time is it?”, and “what room is this?”. These are **textual/template overlap**, not image or data leakage; examples remain in the evaluation sets. Full counts and top templates are in `text_overlap.json`.

The final-holdout contamination scan found zero parsed image-id records in generation outputs, judge labels, metric outputs, reward scores, or manual-inspection artifacts outside the protected manifest. References to the holdout manifest path in code and protocol metadata are retained as provenance and are not examples. See `final_holdout_contamination.json` and the protected freeze in `outputs/phase24/orchestration/protected_hashes.json`.

This decision supports using the existing SFT checkpoint as the paper’s primary baseline. It does not authorize GRPO or change the frozen evaluation protocol.
