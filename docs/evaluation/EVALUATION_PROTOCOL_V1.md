# Evaluation Protocol v1

Phase 2.3 freezes evaluation on the 1,000 image-disjoint development manifest `outputs/evaluation/sft_greedy/val2014_sample1000.jsonl` (hash `36501b7f029d4b8fc04b5736a39641295a694452017cdfda2f269212d69f9c97`). It is a development baseline, not the 2,000-image final holdout. The frozen protocol specifies the same image IDs, prompt, maximum length, and image-processor contract for Zero-shot and final SFT; the reused SFT artifacts have an explicit legacy-provenance caveat in `docs/FINAL_SFT_BASELINE.md`. Greedy output is one question per image; sampled output is four questions per image with `temperature=0.8`, `top_p=0.9`, and `max_new_tokens=32`.

Axis A uses corpus BLEU-4, CIDEr, and `Q-BLEU4-variant`. The latter is the documented local question-type-weighted variant and must not be called standard Q-BLEU4. References are all audited VQAv2 questions in the frozen manifest. Diversity uses Distinct-2 and normalized excess duplicate rate for greedy output; sampled output additionally reports per-image exact unique-question count and rollout unique rate.

Axis B reports the released SeeQ single-question dimensions: Visual Search Difficulty, Visual Evidence Coverage, Visual Context Reasoning, and Visual Spatial Reasoning. The Phase 2.3 audit records the 0–5 rubric and image-level aggregation. The local evaluator uses the released rubric with `gpt-5.6-luna` as a documented judge substitution for paper GPT-5.4; these are not official SeeQ scores. The paper-exact five-question/GPT-5.4 protocol remains unreproduced. Any local evaluator must keep dimensions separate and use an independent judge. VIC is a mechanism diagnostic only: `G_text = L(answer | image, question) - L(answer | question)` and is not a reward weight or master score.

Axis C uses an independent judge and the frozen dimensions premise consistency, reference clarity, and visual answerability. Labels aggregate to Supported, Unsupported, or Uncertain, with failure types missing_entity, wrong_attribute, wrong_relation, ambiguous_reference, unobservable_target, and external_knowledge_required. Parse failures and judge failures are reported separately and excluded from label denominators. The same model, prompt, decoding, and image set are required for both systems.

Axis D reports the diversity metrics above. The released SeeQ embedding evaluator is applied to the existing four-question-per-image project rollouts with Qwen3-Embedding-4B when available; this is a documented four-question project protocol and is not directly comparable to SeeQ’s five-question paper values. No metric is silently substituted.

There is no single master score. Results are a capability profile; this freeze does not authorize GRPO, reward-weight selection, or method claims from one column.

Canonical implementations are `scripts/vvqg/generate.py`, `scripts/vvqg/evaluate.py`, `src/vvqg/evaluation/metrics/`, and `scripts/vvqg/evaluate_visual_support.py`. Canonical generated outputs record model/checkpoint, data hash, decoding, runtime, and output hashes; the reused SFT manifest records the available fields and explicitly marks legacy runtime/backend fields as unknown.
